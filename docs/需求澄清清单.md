# 需求澄清清单

需求文档的技术名词清晰，但验收边界有四处需要与甲方确认。以下按重要性排序，每条给出
我们的默认处理，便于快速对齐——若不另行回复，即按默认方案执行。

## 1. 推理规则由谁执行：OWL 推理机，还是允许规则引擎

- **原文**：任务要求写"推理规则（Axiom）"，举例包含"影响 1200 户""配变过载""负荷转移可行性"。
- **问题**：这三类分别是求和、数值比较、容量比较。OWL 的公理体系不做聚合，数值比较也只能
  用 datatype facet 表达而无法被 OWL 2 RL 推理机执行。若严格要求"全部结论由 OWL 推出"，
  则户数与过载两条必须换实现方式，答案形态也会变。
- **默认处理**：双层推理。结构层（类归属、上下游传递、基数约束、不相交）由 OWL 承担；
  数值与状态相关的判定由规则引擎承担，结论再断言回本体做一致性校验。该取向在
  `docs/设计文档.md` 第二节已作为设计取舍写明。
- **需确认**：甲方是否接受"OWL + 规则引擎"的混合实现；若要求纯 OWL，请告知验收口径。

## 2. demo 的运行环境

- **原文**："demo 系统，本体可视化、agent 对话推理"。
- **问题**：未说明部署形态（本地 / 服务器）、演示现场能否联网、使用哪家模型。
- **默认处理**：本地运行，浏览器访问 `http://127.0.0.1:8000`；默认离线模式，不联网也能完整
  演示；接在线模型只需在 `.env` 中填 base_url 与 key。会议室断网时无需改动即可继续演示。
- **需确认**：演示场地是否有网络；是否需要提前部署到甲方内网服务器。

## 3. 5 个推理问题由谁出

- **原文**："设计 5 个推理问题（如'S1 断开后哪些用户失电'），给出预期答案"。
- **问题**：字面是乙方自拟；实际评审常临时追加"如果 S2 也断开呢"这类追问。
- **默认处理**：自拟 8 题——5 道指定题 + 3 道边界题（可行转供、不可行转供、无解场景），
  全部写成可执行断言。规则按"原子能力"设计（12 条），临时追问可现场组合，不依赖预设题库。
- **需确认**：是否有指定的题目清单或评分表。

## 4. 数据来源与保密

- **原文**：未提及数据。
- **问题**：若使用电力公司真实拓扑，涉及数据脱敏与能否出网的问题；若用虚构数据，需说明
  与真实网架的差异。
- **默认处理**：使用虚构样例（城东 110kV 变电站、F01/F02 两条馈线、8 台配变、2440 户），
  规模与结构贴近真实配网，类名对齐 IEC 61970 CIM，便于后续替换为真实 CIM/XML 导入。
- **需确认**：是否需要接入真实数据；如需，请提供导出格式与脱敏要求。
