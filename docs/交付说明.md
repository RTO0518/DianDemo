# 配电网本体模型构建与知识推理

面向配电网运行与调度的领域本体与推理系统。本体定义"概念、关系、规则"，推理引擎回答
"馈线停电影响哪些用户""配变过载应如何处置"这类推理性问题，Web 界面用于演示与验证。

对应需求文档的五项交付：

| 需求 | 交付物 | 位置 |
| --- | --- | --- |
| 1. 本体模型设计（≥15 类、属性、≥8 条公理） | 28 个类、28 个对象属性、18 个数据属性、16 条公理，YAML 源码 + OWL/TTL | `ontology/` |
| 2. 推理验证（5 个问题 + 预期答案） | 8 道题（5 题指定 + 3 题边界），全部可执行断言 | `app/reasoner/verify.py`、`tests/` |
| 3. 本体可视化 | 类层次关系图 + 电网单线图 + 推理路径 | `web/` |
| 4. 设计文档（800 字） | 818 字，另附 .docx | `docs/设计文档.md`、`docs/配电网本体模型设计说明.docx` |
| 5. demo 系统 | 七页签 Web 系统，含 agent 对话推理 | `app/`、`web/` |

在五项交付之外，按甲方架构方案补充了四个工程能力（详见 `docs/架构方案评估与采纳说明.md`）：

| 补充能力 | 作用 | 位置 |
| --- | --- | --- |
| 数据接入与治理 | 甲方台账 CSV → 14 条规则校验 → 三元组预览 | `app/ingest/`、`data/templates/` |
| SPARQL 只读查询 | 在 OWL 闭包图上检索，换问法不改代码 | `app/api/sparql.py` |
| 阈值可配置 | 80%/100% 等演示值改为可调，推理链注明来源 | `data/thresholds.yaml` |
| 运行审计与版本 | 问答/推理/查询全留痕，本体版本用内容哈希 | `app/audit.py` |

## 快速启动

```bash
# 依赖（Python 3.10+）
pip install -r requirements.txt

# 重建本体与实例（改了 YAML 之后需要执行）
python ontology/build.py

# 启动
python run.py                 # 默认 http://127.0.0.1:8000
```

浏览器打开 `http://127.0.0.1:8000` 即可。首次启动会自动加载本体，无需额外初始化。

## 模型配置

默认使用 **mock 离线模式**，不填任何密钥就能完整演示——推理与数字均来自引擎，只是把
自然语言翻译这一步换成正则匹配。接在线模型时改 `.env`：

```bash
LLM_PROVIDER=openai_compat
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-xxxxxxxx
```

**给甲方做本地化部署时只改一行 base_url，代码不动**（vLLM、Ollama、Xinference、LM Studio
都兼容 OpenAI 协议）：

```bash
LLM_BASE_URL=http://127.0.0.1:8000/v1      # 本地 vLLM
LLM_BASE_URL=http://127.0.0.1:11434/v1     # 本地 Ollama
```

模型适配层在 `app/agent/llm/`，接口协议见 `base.py`。上层 Agent 只依赖 `LLMProvider.chat()`，
换模型不影响推理与工具调用。

## 界面说明

1. **本体模型**：左侧类层次图（实体 → 六个分支 → 具体类），点击查看属性、公理与实例；
   顶部版本条给出本体/实例/阈值三份文件的内容哈希，作为版本凭证。
2. **电网拓扑**：单线图，点击任意开关模拟分合闸，失电区实时变红并给出户数与转供建议。
3. **图谱查询**：SPARQL 只读查询，8 条示例点开即用；默认在 OWL 闭包后的推理图上执行。
   `Ctrl+Enter` 执行；写操作会被明确拒绝并说明原因。
4. **数据接入**：上传台账与拓扑 CSV（自动识别 UTF-8/GBK），得到列映射结果、逐行问题清单
   与三元组预览。**只做校验与预览，不会改动演示环境的运行数据。**
5. **智能问答**：自然语言提问，右侧同步显示推理链（调了哪个工具、依据哪条规则）。
6. **规则验证**：8 道题并排显示"预期 / 实际"，一键重跑；下方是阈值配置（拖动即生效）
   与 12 条规则清单、OWL 自检入口。
7. **运行审计**：每次问答、推理、查询、接入的时间、动作、摘要、命中规则、耗时。

## 五个推理问题的答案（摘要）

| 问题 | 答案 |
| --- | --- |
| S1 断开后哪些用户失电 | 金桥小区 500 户、阳光花园 400 户、城东工业园 300 户，合计 1200 户 |
| 能否转供 | 可经联络开关 L1 转至 F02 线，转移 1000 kW，恢复 1200 户，对侧负载率 20%→45% |
| 哪些配变过载 | 配变 B 过载（105%），配变 F 重载（80%） |
| F01 出口跳闸怎么办 | 全线 1830 户失电，经 L1 转 1700 kW 至 F02，负载率 62.5% |
| F02 高峰 3400 kW 还能转吗 | 不能，备用 600 kW，缺口 400 kW |

完整结果见 `docs/推理验证报告.md`。

## 已知限制

- OWL 2 RL 不执行基数约束的实例校验（A3~A7），这部分由规则 R10 承担；演示中发现的数据质量
  问题会由 R10 报出，而不是由推理机报不一致。
- 样例数据按功率因数约 1 折算，容量与负荷统一用 kW；接入真实数据时应改为 kVA + 功率因数。
- 单线图为固定布局，新增设备需要在 `web/app.js` 的 `LAYOUT` 中补坐标（否则落在默认位置）。
- agent 的对话理解依赖模型；mock 模式只覆盖常见问法，复杂追问请接在线模型。
- **数据接入只做校验与三元组预览，不自动替换运行数据**。这是有意的：演示实例是 8 道验证题
  的基础，被一份尚未确认的台账覆盖会让整个演示连锁失效。确认无误后由实施人员替换
  `data/grid-instances.ttl` 并重启。
- 转供结论只做容量与拓扑校验，**未做**保护定值、相序、短路电流、电压降落校核，
  只能作为候选方案，不能直接作为调度指令。
- 未实现用户登录与角色权限（演示系统无多用户场景）；生产化时需补。
